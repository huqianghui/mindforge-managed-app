# 01 项目现状剖析

> 基线：`main@5c48c7d`，内容 `mindforge@8f2aa16`，`@microsoft/managed-apps-cli 0.31.0`，2026-10-26 检查。
> 本文只描述代码里**已经有的东西**，新功能的设计见 [04 新功能开发指南](04-新功能开发指南.md)。

## 一句话

一个 **React 19 + Vite 8 + MUI 9** 的纯前端 SPA。内容（386 篇 Markdown、187 张图片、知识图谱 JSON）在构建前由脚本从公开仓库 `huqianghui/mindforge` 同步进 `public/`，打包后作为静态资源发布到 Copilot Managed Runtime。目前**没有调用任何 SDK 或 Connector**——`ms.config.json` 里 `connectionReferences` 是空的，应用代码里也没有 import `@microsoft/managed-apps`。

## 运行时结构

```text
managedapps.cloud.microsoft/apps/<app-id>          宿主（Entra 登录、治理壳层）
  └─ iframe: apps-<app-id>....powerplatformusercontent.com
       └─ index.html → /assets/index-*.js         本项目的打包产物
            ├─ fetch /content/manifest.json        文章索引
            ├─ fetch /content/d/<hash>.md          单篇文章（按需）
            ├─ <img src=/content/i/<hash>.png>     图片（按需、lazy）
            └─ fetch /wiki-graph.json              图谱数据（进入图谱页时）
```

因为应用跑在 iframe 里，且宿主不保证把任意路径回退到 `index.html`，所以路由用 **hash**，Vite `base` 用 `'/'`。

## 路由

`App.tsx` 里的 `parseHash()` 是唯一的路由表：

| hash | 视图 |
|---|---|
| `#/graph` | 知识图谱 |
| `#/doc/<urlencoded path>` | 文章，`path` 是 mindforge 仓库里的原始路径，例如 `Azure/xxx.md` |
| `#/doc/<path>?a=<anchor>` | 文章并滚动到锚点（锚点由 `rehype-slug` 生成） |
| 其他 | 回到 `README.md` |

生成链接一律用 `docHash(path, anchor?)`，不要手拼。新增页面时扩展 `Route` 联合类型和 `parseHash()`，并在顶部 `Tabs` 加一项（见 04）。

## 两份数据

### `public/content/manifest.json`

```ts
interface ContentManifest {
  generatedAt: string;          // 同步时间（UTC ISO）
  sourceCommit?: string;        // mindforge 的短 commit
  docs: { path: string; title: string; file: string }[];   // file = d/<sha1(path)[:12]>.md
  assets: Record<string, string>;                          // 原图片路径 → i/<hash>.<ext>
}
```

当前规模：386 篇（`Notes` 166、`wiki` 165、`Azure` 30、`paper` 14、`product` 6、`book` 4、`README.md` 1），`public/content` 共 41 MB，主要是图片。

**manifest 里没有字数、标签、日期、链接**——这些都在 Markdown 正文或 front matter 里，前端要用就得逐篇 fetch。路线图第 3 阶段（文档统计）的第一件事就是在同步脚本里把这些字段预计算进 manifest。

### `public/wiki-graph.json`

由 mindforge 仓库的 wiki 导出脚本生成，这里只是复制。结构见 `src/types.ts`：

| 实体 | 数量 | 关键字段 |
|---|---|---|
| node | 147 | `type`（concept 117 / method 22 / decision 8）、`category`、`tags`、`claims_count`、`avg_confidence` |
| claim（嵌在 node 里） | 806 | `statement`、`confidence`（0.3–0.9，集中在 0.7/0.8）、`status`（active 395 / stale 411）、`source`（来源文章标题）、`first_seen`、`last_updated`（2026-04-11 至 2026-10-24）、`evidence?` |
| link | 516 | `relation_type`（10 种，contrasts/uses 最多）、`description` |
| category | 13 | `members` 共覆盖 117 个节点 |

几个对后续功能有用的观察：

- **30 个节点 `category` 为空串**，也不在任何 category 的 `members` 里。做"按分类筛选"时要给它们一个"未分类"桶。
- **一半以上的 Claim 是 `stale`**。这是"建议卡片"（第 2 阶段）最直接的素材。
- 当前没有孤立节点（每个节点至少一条边）。
- `claim.source` 是来源文章的**标题**（多为去掉空格的形式）而不是路径；`NodePanel.tsx` 目前只把它当文本显示。要从 Claim 跳回原文，得自己用 manifest 的 `title` 或文件名做匹配。节点本身跳 wiki 页用的是 `index.byStem.get(node.id)`（`NodePanel.tsx:78`）。

## 内容同步：`scripts/sync-content.py`

1. 浅克隆或更新 `https://github.com/huqianghui/mindforge.git` 到 `.cache/mindforge`（已 gitignore）；也可传本地路径。
2. `git ls-files` 只取**被跟踪**的文件——源仓库的公开边界就是应用的内容边界。
3. 取 `README.md` 与 `Notes/ Azure/ paper/ book/ product/ wiki/` 下的 `.md`。
4. 用正则抓文中引用的本地图片（Markdown 与 `<img>` 两种写法），只复制被引用且被跟踪的。
5. 文件名改为路径 SHA-1 前 12 位，避开中文文件名在打包和 URL 上的问题。
6. 写 `manifest.json`，复制 `wiki/wiki-graph.json`。

**会整个删除并重建 `public/content/`**，所以不要在这个目录里手写文件。

## 发布：`scripts/release.sh` 与两个远端

```text
github   ← 源码与学习记录（不含 ms.config.json）
platform ← Managed Runtime 平台托管仓库，平台从这里构建
```

`ms.config.json` 含租户内的 `appId / environmentId / repositoryId`，不进 GitHub；但平台构建要求它在仓库树里。脚本的做法：

1. 同步内容、本地 `npm run build` 验证。
2. 提交并 `git push github main`。
3. 用临时 index 在 `HEAD` 上叠一个只加了 `ms.config.json` 的提交（不碰工作区）。
4. `git push platform +<该提交>:refs/heads/main`，再 `ms app deploy --commit <该提交>`。

结论：**平台仓库的 `main` 永远是"GitHub main + 1 个配置提交"，只在本仓库开发。**

> 加了 Connector 以后，`ms app add data-source` 会把连接信息写进 `ms.config.json` 的 `connectionReferences`，并生成 TypeScript 代码。生成的代码要进 GitHub，`ms.config.json` 仍然不进——这套机制不用改，但 `ms.config.example.json` 要同步更新结构（把真实 ID 换成占位符），否则新同事无法复现。见 [02](02-Managed-Runtime与SDK参考.md#connectionreferences-与仓库策略)。

## 本地开发

```bash
npm install
python3 scripts/sync-content.py   # 首次或内容更新后
npm run dev                       # 纯前端预览，localhost:5173
```

`npm run dev` 跑的是普通 Vite，**没有宿主**：`getUser()`、Connector 调用都不可用。需要这些能力时改用 `ms app dev`（见 02）。
