# 10 参考应用拆解与常见功能实现模式

> 学习系列第 6 篇。拆解一个已上线的 managed app（CSU Investment Insights），把它的功能归纳成可复用的实现模式，再映射到本项目。
> 2026-10-27 用你的账号在浏览器里打开该应用，查看页面结构、网络请求和前端 bundle。**只记录技术结构，不记录业务数据**；分析用的 bundle 与页面快照已从本地删除。

## 一、一眼看全貌

| 项 | 观察 |
|---|---|
| 页面 | Overview、Planning、Explorer、Case Board 四个视图；右上角 Ask Copilot、Glossary 两个面板 |
| 路由 | 路径路由：`/`、`/planning`、`/explorer`、`/case-board`（React Router）。说明应用内的 `history.pushState` 在宿主 iframe 里可用；刷新深层路径是否回退到 `index.html` 未测 |
| 主 bundle | 一个约 3.6 MB 的 JS + 一个 CSS（数据快照打包在里面） |
| 前端库 | React、React Router、TanStack Query、Recharts、Radix、Lucide、SheetJS（Excel 导出）、jsPDF + html2canvas（PDF 导出）、少量 d3 |
| Connector | **只有两个**：Work IQ Copilot MCP、SharePoint（见 [08 §5](08-Connector全景.md#五参考应用实例只用两个-connector实测)） |
| 版本提示 | 标题旁 "Live, version 2.4" 徽标 + "What's new in version 2.4" 横幅，可展开看改动 |
| 数据时效 | 页面写明 "labor through <日期> · refreshed <日期>"；提示词里提到 "the Monday email"——数据每周一刷新，同时有一封周报邮件（在应用之外产生） |

架构草图：

```text
           每周一（应用之外）
  ┌──────────────────────────────┐
  │ 数据准备脚本 → 计算指标、建议 │──重新构建并部署──┐
  │ 同时发出周报邮件              │                  │
  └──────────────────────────────┘                  ▼
                                    ┌───────────── managed app ─────────────┐
                                    │ bundle 内：本周数据快照 + 术语表        │
                                    │ Overview / Planning / Explorer / Case  │
                                    │ Board：前端计算、筛选、图表、导出       │
                                    │                                        │
                                    │ Glossary：静态术语                      │
                                    │ Ask Copilot ──▶ Work IQ Copilot MCP ──▶ M365 Copilot
                                    │ 行动项状态、异常值审核 ⇄ SharePoint 列表 │
                                    └────────────────────────────────────────┘
```

## 二、逐个功能拆解

### 2.1 Overview：本周简报

区块：本周日期范围与"待处理 / 待核查 / 无跟进"计数 → 关键指标卡（带"与上周比"）→ "Check first"（Act / Check / Note 三级）→ "What changed"（本周新增与已解决）→ "Top moves" → "Actions"（可按 Open / All / Closed 过滤，"Email owners"）。

| 能力 | 实现模式 |
|---|---|
| 指标卡、与上周对比 | **构建期预计算 + 快照历史**：每周生成一份快照，和上一份比较；页面写明 "first week on record, changes show from next refresh" |
| Check first / Top moves | **规则引擎**：用固定规则从数据里挑出问题和建议，每条带"为什么"的说明 |
| 行动项负责人 | 规则写死在页面说明里（交易级找商机负责人、客户级找主客户经理……），可解释 |
| 行动项状态共享 | **SharePoint 列表**（`CSUInsights-Actions`，主键 `ID`，状态是选项列）：页面说明 "Status is shared with everyone who opens the app" |
| Email owners | **`mailto:` 链接**，预填收件人、抄送、主题、正文；不用 Outlook Connector |
| 导出 | **浏览器端**：Excel 用 SheetJS，PDF 用 jsPDF + html2canvas |

### 2.2 Planning：建议与对比

区块：筛选（年初至今 / Q1 / Q2，价值类型下拉）→ "Recommended moves"（按团队过滤，单选按钮上带每个团队的条数）→ 每条建议分 "WHAT THE NUMBERS SAY" 和 "MOVES" 两段 → "Hours vs. outcome, by …"（投入 / 交付切换）。

模式：**建议卡片 = 规则结论 + 数据依据 + 行动**。数据依据和行动分开写，读者先看证据再看建议。

### 2.3 Explorer：筛选、钻取、图表

（来自你最初的截图）多维筛选（财季、财月、团队、角色、市场、业务单元）→ 两组 KPI 卡 → 月度堆叠柱状图 + 明细表（"Click a month for the team and customer split"）→ 散点图（投入工时 vs 关联价值，带平均线，可按客户 / 业务单元 / 团队切换）。

| 能力 | 实现模式 |
|---|---|
| 多维筛选 | 前端过滤内存中的快照；单选按钮组 + 下拉 |
| 图表联动、点月份钻取 | 点击图表 = 设置筛选条件，所有图表与表格共用同一份筛选状态 |
| 术语下划线 | 指标名带虚线下划线，点击打开 Glossary 并定位到该术语 |

### 2.4 Case Board："侦探墙"

每个团队是一张 "Case file"，旁边挂若干条 "Lead"（线索 / 建议），可缩放、"Re-frame the wall"，侧边 "CASE TRAIL" 记录浏览路径。

模式：**把同一份规则结论换一种可视化**——列表适合逐条处理，墙适合看全局关系。数据和 Planning 的建议是同一来源。

### 2.5 Glossary：术语表

右侧面板 "Glossary and Ask Copilot"，两个标签页：**Terms** 和 **Ask Copilot**；有搜索框；术语按类别分组（阅读说明、工时、比率、各类管道……），中英双语。

模式：**静态术语数据，同时服务三处**：Glossary 面板、页面上的术语下划线、Ask Copilot 的提示词（作为"权威定义"）。每个术语有 id，Ask Copilot 的回答靠 id 关联回术语。

### 2.6 Ask Copilot：最值得学的部分

**调用链**（从 bundle 中的生成代码与调用代码读出）：

```text
用户提问
  │ ① 本地预检索：解析问题里的人、客户、团队等，从快照中找出相关数据行
  │ ② 拼提示词
  ▼
SDK 生成的 Service：CH.mcp_m365copilot(undefined, body)
  │ 数据源 a365copilotchatmcp，动作 mcp_m365copilot
  │ POST /{connectionId}/servers/mcp_m365copilot，可带 Mcp-Session-Id 头
  │ body 是 MCP 的 JSON-RPC：
  │   { jsonrpc: "2.0", id, method: "tools/call",
  │     params: { name: "copilot_chat", arguments: { message: <提示词> } } }
  ▼
Work IQ Copilot MCP Connector ──▶ Microsoft 365 Copilot（以用户自己的身份）
  ▼
返回 JSON-RPC 结果：result.content[] 里的 text 片段
  │ ③ 校验 id 对应、处理 JSON-RPC error
  │ ④ 解析最后一行 "RELATED: id1, id2"，渲染为术语链接
  ▼
显示回答；超过 10 秒显示"仍在处理"提示；最近几轮问答留作上下文
```

**提示词结构**（只描述结构）：

| 段落 | 作用 |
|---|---|
| 角色 | "You are the help assistant inside the … app" |
| 约束 | "Answer ONLY from the GLOSSARY and APP DATA SNAPSHOT below — do not search files, mail or the web" |
| 输出规则 | 用提问的语言回答；中文术语后附应用里的英文标签；最多 120 词；纯文本、不用表格；只用快照里的数字，没有就说没有 |
| 引用协议 | "End with one last line exactly like: RELATED: id1, id2"（术语 id） |
| GLOSSARY | 全部术语的权威定义（带 id） |
| SCOPE / 本周简报 / 待办 Top 10 | 数据快照摘要，和 Overview 页、周报邮件同源 |
| ROWS FROM THE APP FOR THIS QUESTION | ① 本地预检索出的精确数据行 |
| EARLIER IN THIS CONVERSATION | 最近几轮问答 |
| QUESTION | 用户的问题 |

这套做法解决了前几篇里遇到的三个难题：

| 难题 | 它的解法 |
|---|---|
| Connector 只返回纯文本，没有结构化引用（[03](03-Copilot-Studio集成指南.md)） | **在提示词里约定一个输出协议**（`RELATED:` 行），应用自己解析 |
| 模型可能编数字 | **数字由应用算好塞进提示词**，并要求"只用快照里的数字"；页面写明 "Figures come straight from this week's data; definitions come from Copilot" |
| GitHub Copilot harness 的 agent 调不了（[05](05-Copilot-Studio-Harness对比.md)） | **不用 Copilot Studio agent**，直接调 M365 Copilot（Work IQ），用户以自己的身份、不用建 agent |

代价：Work IQ API 按量单独计费（[05 §5](05-Copilot-Studio-Harness对比.md#五计费速记)）；回答受提示词长度限制，快照不能太大；依赖 Preview 的 Connector。

### 2.7 异常值审核：人在回路

"N outliers to review" 弹窗：明显异常的金额"在审核前不计入合计"；审核决定写进 **SharePoint 列表 `CSUInsights-OutlierReviews`**（主键 `ID`，决定是选项列）。

模式：**静态快照 + 一张共享的"人工判断"表**。数据是周更的，但人对数据的判断是实时共享的，下次刷新时脚本也能读到这些判断。这就是 [07](07-Agent-Workflow-App协作模式.md) 里"共享数据"模式的最小版本——连 workflow 都不需要。

## 三、模式清单

| # | 模式 | 一句话 | 用到的平台能力 |
|---|---|---|---|
| P1 | 构建期快照 | 数据定期算好打包进应用 | 无（静态） |
| P2 | 快照历史对比 | 保留上一期快照，算"本周变化" | 无 |
| P3 | 规则建议 | 固定规则产出问题 / 建议，每条带依据 | 无 |
| P4 | 共享筛选状态 | 所有图表、表格读同一份筛选条件，点图即筛选 | 无 |
| P5 | 术语即数据 | 一份术语表服务面板、页面标注、AI 提示词 | 无 |
| P6 | 共享状态表 | 用户的标记 / 决定写进 SharePoint 列表，所有人可见 | SharePoint Connector |
| P7 | 浏览器原生能力 | `mailto:`、浏览器端导出 Excel / PDF | 无 |
| P8 | 提示词落地问答 | 本地预检索 + 权威定义 + 输出协议，调 M365 Copilot | Work IQ Copilot MCP Connector |
| P9 | 版本与时效透明 | 版本号、更新说明、数据截止日期写在页面上 | 无 |

**九个模式里七个不需要任何 Connector。**

## 四、映射到本项目

| 模式 | 参考应用 | Mindforge 可以怎么用 | 对应路线图 |
|---|---|---|---|
| P1 快照 | 每周数据快照 | 已有：`sync-content.py` 同步文章与图谱；可以再预计算字数、链接、标签 | 阶段 3 |
| P2 历史对比 | 与上周比 | 保留上一次的 `wiki-graph.json`，算"新增节点 / 新变 stale 的 Claim" | 阶段 1–2 |
| P3 规则建议 | Check first / Recommended moves | stale Claim、低置信度、薄弱分类、未分类节点（[04](04-新功能开发指南.md) 阶段 2 的规则） | 阶段 2 |
| P4 共享筛选 | Explorer | 洞察页：分类 × 状态 × 置信度 × 时间 | 阶段 1 |
| P5 术语即数据 | Glossary | **wiki 节点本身就是术语表**（147 个概念 / 方法 / 决策，带摘要和标签），可直接做 Glossary 面板和正文术语标注 | 新增 |
| P6 共享状态表 | 行动项状态、异常值审核 | "这条 Claim 已复核 / 仍成立 / 已过时"写进 SharePoint 列表；或第 4 阶段的阅读进度、收藏 | 阶段 2、4 |
| P7 浏览器原生 | mailto、导出 | 导出洞察表为 Excel；生成某篇文章的 PDF | 可选 |
| P8 提示词问答 | Ask Copilot | 用 Work IQ Copilot MCP：本地 Fuse.js 检索相关文章段落和 wiki 节点 → 拼提示词 → 回答末尾 `RELATED: <节点 id 或文章路径>` → 渲染成应用内链接 | 阶段 5（替代或对比 Copilot Studio agent） |
| P9 透明 | 版本与刷新日期 | 已有 `mindforge@<commit>`；可加版本号与"本次更新了什么" | 小改 |

**和 GitHub Pages 的区别**：P1–P5、P7、P9 在 GitHub Pages 上也能做；**P6（共享状态）和 P8（以用户身份调用 M365 Copilot）只有 managed app 能做**，再加上"只有登录的内部用户能看"这一点。下一篇方案讨论会围绕这三点展开。

## 五、实测中的两个副产品

1. **SSO Connector 的连接会被静默创建。** 打开参考应用时，平台自动为当前账号 `PUT` 了两个连接（Work IQ Copilot MCP、SharePoint，返回 201），随后同意框消失、应用开始读数据。对用户来说就是"打开即用"；对管理员来说，用户的连接列表里会多出这些连接。
2. **宿主会上报 API 消耗。** 网络里有 `appframework/apps/<id>/reportApiConsumption?host-mode=Runtime` 和 `monitoringhub/.../logDataRequests`，对应 [06](06-托管位置与连接链路.md) 和 [08](08-Connector全景.md) 里讲的"每次 Connector 调用计费"。
